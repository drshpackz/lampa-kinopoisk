# Кинопоиск — плагин для Lampa

Добавляет вкладку **«Кинопоиск»** в общий поиск Lampa и умеет открыть карточку
найденного тайтла — с описанием, рейтингами КП и IMDB, жанрами, актёрами,
сезонами и сериями.

Каталога и пункта в меню намеренно нет: бесплатные токены Кинопоиска считаются
**сотнями запросов в сутки**, а лента из двух десятков рядов съедала бы дневной
лимит за одно открытие. Поиск — это один запрос, карточка — ещё один.

## Установка

1. Lampa → **Настройки → Расширения**.
2. Добавьте плагин по ссылке:
   ```
   https://drshpackz.github.io/lampa-kinopoisk/kinopoisk.js
   ```
3. Перезапустите Lampa. В поиске рядом с CUB и TMDB появится вкладка
   **«Кинопоиск»**.

## Токены: два вместо одного

Плагин работает с двумя независимыми API Кинопоиска. Они взаимозаменяемы,
потому что оба ключуются **одним и тем же id Кинопоиска**: если у первого
кончился лимит или не принят токен — запрос молча уходит ко второму.

| Провайдер | Бесплатно | Где взять ключ |
|-----------|-----------|----------------|
| `kinopoisk.dev` (api.poiskkino.dev) | 200 запросов/сутки | бот [@poiskkinodev_bot](https://t.me/poiskkinodev_bot) |
| `kinopoiskapiunofficial.tech` | 500 запросов/сутки | регистрация на [kinopoiskapiunofficial.tech](https://kinopoiskapiunofficial.tech/) |

Оба ключа вставляются в **Настройки → Кинопоиск**. Со своими ключами получается
**700 бесплатных запросов в сутки** вместо 200.

> **Встроенный токен общий.** Если поле `kinopoisk.dev` пустое, используется
> зашитый в плагин ключ — один на всех, кто поставил плагин по ссылке выше. Его
> 200 запросов делит вся аудитория, поэтому он регулярно упирается в лимит.
> Свой ключ здесь не «на всякий случай», а нормальный режим работы.

Первым идёт `kinopoisk.dev`: он отдаёт актёров и похожие тайтлы **вместе** с
карточкой, то есть тратит на неё меньше запросов. У `kinopoiskapiunofficial`
актёры — отдельный запрос, и плагин его не делает: на вкладке поиска состав не
главное, а каждый запрос стоит суток лимита.

### «Токен не принят» ≠ «лимит исчерпан»

Кинопоиск отвечает двумя разными статусами, и плагин их не путает:

| Ответ | Что значит | Что делать |
|-------|------------|------------|
| `401` «Переданный токен некорректен» | токен неверный | проверить его в Настройки → Кинопоиск |
| `403` «Вы израсходовали ваш суточный лимит» | токен **рабочий**, кончились запросы | добавить второй токен или подождать сброса |

Получив `403`, плагин закрывает этого провайдера до конца суток и переходит к
следующему: встроенный токен общий, и его сутки могут израсходовать чужие
устройства, так что своему счётчику доверять нельзя — сервер главнее.

## Расход запросов

- **Поиск** — 1 запрос. Результат живёт в кеше 6 часов, повторный тот же
  запрос бесплатен.
- **Карточка фильма** — 1 запрос, кеш на неделю.
- **Карточка сериала** — 2 запроса (карточка + сезоны). Ни один из двух API не
  отдаёт сезоны вместе с карточкой. Запрос сезонов ровно тот же, что потом
  делает экран серий, поэтому открыть серии после карточки — бесплатно.
- **«Ещё»** — по запросу на страницу.

Кроме этого: очередь не больше двух одновременных запросов и 220 мс между
стартами (у kinopoisk.dev потолок 5 запросов/сек), `selectFields` чтобы не
тащить весь документ на телевизор, и кеш разобранных ответов в `Lampa.Storage`
(до 90 записей, вытесняются самые старые). Когда лимиты кончились, плагин
отдаёт сохранённую копию вместо пустого экрана.

## Как устроено

Один файл `kinopoisk.js`, чистый ES5, зависимости — только глобальные `Lampa`
и `$`. Плагин регистрирует источник:

```js
Lampa.Api.sources.kp = { search, discovery, list, full, seasons, ... }
```

`discovery()` — это и есть вкладка в поиске. Каталожные методы (`main`,
`category`, `menu`) отвечают честным отказом: Lampa может позвать любой метод
источника, и пустой ответ лучше исключения в чужом компоненте.

### Кинопоиск → карточка Lampa

Два правила, которые оба адаптера обязаны соблюдать (закреплены тестами):

1. **Фильм получает только `title`/`original_title`, сериал — только
   `name`/`original_name`.** Lampa решает, чем открыть карточку, по наличию
   `original_name` (`router.add('full')`: `method = data.original_name ? 'tv' :
   'movie'`). Проставить оба набора — значит открыть фильм как сериал.
2. **`poster_path` не заполняется никогда.** У Кинопоиска готовые абсолютные
   URL, а `Api.img()` всегда подставляет хост TMDB. Картинки идут в `poster`,
   `img` и `background_image` — их Lampa берёт как есть.

Рейтинг Кинопоиска кладётся в `vote_average`: на полной карточке Lampa
переименовывает первый бейдж в имя источника, так что он и подписан «KP».
Отдельного `kp_rating` нет — иначе та же оценка выводилась бы дважды.

Различия между API спрятаны в двух объектах-провайдерах (`KPDEV` и `KPU`):
каждый умеет построить путь и разобрать ответ в **одну и ту же** карточку.
Всё остальное в файле о различиях не знает.

### Чего нет

- **Каталог и пункт меню** — убраны ради лимитов (см. выше).
- **Трейлеры.** Кинопоиск отдаёт ссылку на свой embed-плеер без
  YouTube-ключа, а плеер трейлеров Lampa ждёт именно ключ. Заведомо нерабочая
  кнопка хуже её отсутствия.
- **Страница актёра** — заглушка: фильмографию пришлось бы тянуть отдельными
  запросами, а они на счету.

## Тесты

```bash
npm test              # 67 юнит-тестов на моке Lampa: без сети и без расхода квоты
npm run test:live     # живая проверка против настоящих API (~6 запросов)
npm run test:browser  # плагин внутри настоящей Lampa в браузере
```

`npm test` намеренно ограничен `test/*.test.js`: живые проверки тратят реальную
суточную квоту, поэтому запускаются только вручную.

Юнит-тесты гоняют плагин на моке Lampa (`test/helpers/lampa-mock.js`) с
фикстурами **обоих** API — так проверяется, что карточка одинаковая, откуда бы
она ни пришла, и что переключение провайдеров срабатывает на `401`, `403` и
сетевой ошибке. Но мок не скажет, что путь запроса неверный или поле
переименовали, поэтому есть две живые проверки:

- **`test:live`** — реальные ответы через настоящий сетевой слой плагина.
  Второго провайдера можно включить ключом:
  ```bash
  KPU_TOKEN=<ваш ключ> npm run test:live
  ```
- **`test:browser`** — Lampa целиком в headless-браузере: плагин ставится в
  работающее приложение, проверяется вкладка в поиске, отсутствие пункта меню,
  поиск и открытие карточки. Нужен запущенный билд Lampa:
  ```bash
  git clone --depth=1 https://github.com/yumata/lampa /tmp/lampa
  python3 -m http.server 8901 --directory /tmp/lampa &
  NODE_PATH=<путь к node_modules с playwright> npm run test:browser
  ```
  Скриншоты кладутся в `test/live/shots/`.

## Совместимость

Проверено на сборке Lampa 333 (`yumata/lampa`). Плагин не трогает встроенные
источники: `tmdb` и `cub` остаются на месте, `kp` добавляется рядом. Если
Кинопоиск был выбран основным источником прошлой версией плагина, при запуске
источник возвращается на TMDB — каталога больше нет, и главная была бы пустой.
